# - GL backend, a multisampled texture the app also reads (D3D11_BIND_SHADER_RESOURCE): emulated, not exact for one
#   case. wgpu-hal attaches a sampleable GL multisample texture through glFramebufferTexture2DMultisampleEXT (the
#   EXT_multisampled_render_to_texture entry, for single-sample textures), so nothing drawn or cleared reaches it,
#   and no copy can write it. Such a texture is a renderbuffer now (it draws and resolves exactly) and a shader's
#   Texture2DMS reads its resolved copy (D3DDevice.MsReadsResolved; D3DMultisampleReadTests matches WARP for a
#   shader that averages the samples). Left: Load(sample i) of an edge pixel reads the pixel's resolved value, not
#   that sample's. Exact per-sample reads cannot be had on this backend: a renderbuffer's samples reach nothing but
#   a resolve (an average), and a second rasterization per sample (viewport shifted to sample i) shades at the
#   sample position where D3D shades at the pixel centre. The fix is in wgpu-hal (glFramebufferTexture2D for a
#   TEXTURE_2D_MULTISAMPLE target). Depth multisampled textures are not emulated (WebGPU resolves no depth).
